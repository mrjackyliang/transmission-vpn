Plan the `/config` and `/data` folders so the container can start, keep its state, and write your downloads.

## Volume Layout

```text title="Container paths"
/config
|-- keys/                 # Mode 0700, owned by PUID:PGID
|   `-- installation.key  # 64 lowercase hex characters plus newline, mode 0600
|-- database/
|   `-- state.sqlite3     # Database, with -wal and -shm files beside it
|-- transmission/         # Transmission's configuration folder, owned by PUID:PGID (0750)
|   `-- settings.json     # Rebuilt at every start
|-- vpn/                  # Reserved app state
`-- managed.json          # Optional managed configuration
/data
|-- downloads/            # Default profile's download folder
`-- incomplete/           # Default incomplete folder
```

- The <Terminology title="The /config folder; back it up whole, key included" to="/docs/reference/terminology#storage-and-keys">config volume</Terminology> holds the database, the <Terminology title="Unlocks your saved secrets; lose it and they're removed" to="/docs/reference/terminology#storage-and-keys">installation key</Terminology>, and Transmission's own files, so it is recommended to back it up as one unit, as covered in [Updates and Backups](/docs/operations/updates-and-backups/).
- When the <Terminology title="Unlocks your saved secrets; lose it and they're removed" to="/docs/reference/terminology#storage-and-keys">installation key</Terminology> is missing at start, the container makes a new one, removes VPN endpoint profiles and credentials (WireGuard keys included) and the notification secrets, disables the saved VPN connections, and turns off the authenticator app, as covered in [Updates and Backups](/docs/operations/updates-and-backups/#missing-installation-key).
- The <Terminology title="The /data folder where every download lives" to="/docs/reference/terminology#storage-and-keys">data mount</Terminology> holds every profile's downloads and the incomplete folder.

## Runtime Identity

| Identity                                                                                                                                                                                                                                                                                              | Runs                                                                                                                                                                                                                                                                        |
|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PUID`</Terminology>:<Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PGID`</Terminology>, `1000:1000` by default | The control API, directory controller, Transmission runner and daemons, and web proxy. s6 applies the numeric IDs directly; the image has no fixed service account with a different UID.                                                                                    |
| `root` (`0:0`)                                                                                                                                                                                                                                                                                        | s6-overlay, Nova's initialization, firewall setup, and the <Terminology title="The only part allowed to bring tunnels up or down" to="/docs/reference/terminology#container-and-services">VPN controller</Terminology>. s6 drops every unprivileged service to `PUID:PGID`. |

- <Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PUID`</Terminology> and <Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PGID`</Terminology> must be integers from 1 to 60000.
- Start the container as root, such as with `--user 0:0`. s6 needs root for initialization and networking, then runs every unprivileged service as the configured numeric IDs.
- Use the host account and group that own the download folders. Every app-state file is also owned by those IDs.

## Ownership and Permissions

At every start, the container prepares its folders before any service runs:

1. Nova resolves the app-state directory, normally `/config`, and creates `keys/` and `database/` there.
2. It recursively changes the complete app-state directory to `PUID:PGID` on every start.
3. It sets `keys/` to mode `0700` and every file in it to `0600`.
4. It creates the app-specific `transmission/` and `vpn/` folders, then gives `/data` itself to `PUID:PGID` without recursively changing existing downloads.
5. It checks that `PUID:PGID` can write `/data`, migrates an old app layout when present, and installs Transmission's settings file with mode `0600`.

Every state file under `/config` belongs to `PUID:PGID`. Existing content below `/data` keeps its ownership, except during the temporary deprecated `/data` state fallback, where `/data` is the active state directory and Nova must own it recursively.

When the download check fails, the container stops with a line ending in `/data is not writable by PUID <id> and PGID <id>.` It is recommended to give the host folder to those IDs, or set the variables to the folder's current owner.

## Download Folders

- Every profile folder and the incomplete folder must be an absolute path inside `/data`, with no `..` segments and no trailing slash. `/data` itself cannot hold torrent data.
- Each profile owns one folder. The folder cannot be the incomplete folder, sit beneath it, or belong to another profile. No profile's folder can sit inside another profile's folder or contain one, the **Default profile**'s included.
- The **Default profile**'s folder is `transmission.downloadDirectory`, `/data/downloads` by default. An edit applies without a restart and asks for **Save and move** when torrents use the profile.
- Saving any profile creates its download folder and missing parents. The control API also creates the enabled incomplete folder when it is missing.
- These automatic folders and folders created from the folder browser get mode `0775` and belong to `PUID:PGID`.
- The folder browser refuses symbolic links, even ones that point inside `/data`.

:::tip
To keep downloads on more than one host folder, mount each one at its own path inside `/data`, such as `/data/movies`, instead of linking folders together.
:::

## Timezone

- `TZ` sets the container's time zone, and the default is `UTC`.
- Nova's initialization links the matching zone into `/etc/localtime`, writes it to `/etc/timezone`, and also leaves `TZ` in the service environment.
- It must name an installed IANA zone such as `Europe/London`. An unknown zone stops startup.
