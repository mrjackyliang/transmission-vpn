Plan the `/config` and `/data` folders so the container can start, keep its state, and write your downloads.

## Volume Layout

```text title="Container paths"
/config
|-- app/                  # Control plane state, owned by PUID:PGID (2770)
|   |-- state.sqlite3     # Database, with -wal and -shm files beside it
|   `-- keys/             # Owned by PUID:PGID (2770)
|       `-- installation.key
|-- transmission/         # Transmission's configuration folder, owned by PUID:PGID (0750)
|   `-- settings.json     # Rebuilt at every start
|-- vpn/                  # Owned by PUID:PGID (2770), currently unused
`-- managed.json          # Optional managed configuration
/data
|-- downloads/            # Default profile's download folder
`-- incomplete/           # Default incomplete folder
```

- The <Terminology title="The /config folder holding state, keys, and settings" to="/docs/reference/terminology#config-volume">config volume</Terminology> holds the database, the <Terminology title="Key that encrypts saved secrets, such as VPN logins" to="/docs/reference/terminology#installation-key">installation key</Terminology>, and Transmission's own files, so it is recommended to back it up as one unit, as covered in [Updates and Backups](/docs/operations/updates-and-backups/).
- When the <Terminology title="Key that encrypts saved secrets, such as VPN logins" to="/docs/reference/terminology#installation-key">installation key</Terminology> is missing at start, the container makes a new one, removes VPN endpoint profiles and credentials (WireGuard keys included) and the notification secrets, disables the saved VPN connections, and turns off the authenticator app, as covered in [Updates and Backups](/docs/operations/updates-and-backups/#missing-installation-key).
- The <Terminology title="The /data folder that holds all downloads" to="/docs/reference/terminology#data-mount">data mount</Terminology> holds every profile's downloads and the incomplete folder.

## Runtime Identity

| Account        | IDs                                                                                                                                                                                                                                                                                                        | Runs                                                                                                                                                                                                   |
|----------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `transmission` | <Terminology title="User and group IDs that own Transmission's files" to="/docs/reference/terminology#puid-and-pgid">`PUID`</Terminology> and <Terminology title="User and group IDs that own Transmission's files" to="/docs/reference/terminology#puid-and-pgid">`PGID`</Terminology>, `1000` by default | Transmission and the <Terminology title="Helper that lists, creates, and deletes empty folders under /data" to="/docs/reference/terminology#directory-controller">directory controller</Terminology>   |
| `control`      | UID and GID 65532, and a member of the `PGID` group                                                                                                                                                                                                                                                        | The <Terminology title="The service that runs the web interface and API" to="/docs/reference/terminology#control-plane">control plane</Terminology>                                                    |
| `root`         | 0                                                                                                                                                                                                                                                                                                          | Startup checks, the firewall, and the <Terminology title="Privileged service that runs tunnels and switches the firewall" to="/docs/reference/terminology#vpn-controller">VPN controller</Terminology> |

- <Terminology title="User and group IDs that own Transmission's files" to="/docs/reference/terminology#puid-and-pgid">`PUID`</Terminology> and <Terminology title="User and group IDs that own Transmission's files" to="/docs/reference/terminology#puid-and-pgid">`PGID`</Terminology> must be integers from 1000 to 60000, and they can't already belong to another account in the image.
- At start, the container gives the built-in `transmission` account these IDs, so files that Transmission creates belong to them.
- IDs below 1000 aren't accepted, so a host account or group with a lower ID needs a different user or group for the container.

## Ownership and Permissions

At every start, the container prepares its folders before any service runs:

1. It changes the owner of `/config` and `/data` themselves to the Transmission account, but only when they're owned by `root:root`.
2. It gives `/config/app` and `/config/vpn`, with everything inside them, to `PUID:PGID`. Folders get mode `2770` and files `0660`, so `control` reaches its state through the shared group.
3. It creates `/config/transmission` for the Transmission account.
4. It checks that `control` can write to `/config/app` and `/config/app/keys`, and that the Transmission account can write to `/config/transmission` and `/data`.
5. It installs Transmission's settings file with mode `0600`, owned by the Transmission account.

Every file in `/config` belongs to `PUID:PGID`, so a host tool that gives a whole folder tree to one account, such as a scheduled `chown -R`, keeps working as long as it uses the same IDs. New files that the control plane writes stay group-writable until that tool runs again.

When a check fails, the container stops with a message such as `config-init: /data is not writable by transmission.` It is recommended to give the host folder to the <Terminology title="User and group IDs that own Transmission's files" to="/docs/reference/terminology#puid-and-pgid">`PUID`</Terminology> and <Terminology title="User and group IDs that own Transmission's files" to="/docs/reference/terminology#puid-and-pgid">`PGID`</Terminology> account, or to set those IDs to the folder's current owner.

## Download Folders

- Every profile folder and the incomplete folder must be an absolute path inside `/data`, with no `..` segments and no trailing slash. `/data` itself cannot hold torrent data.
- Each profile owns one folder. The folder cannot be the incomplete folder, sit beneath it, or belong to another profile. No profile's folder can sit inside another profile's folder or contain one, the **Default profile**'s included.
- The **Default profile**'s folder is `transmission.downloadDirectory`, `/data/downloads` by default. An edit applies without a restart and asks for **Save and move** when torrents use the profile.
- Saving any profile creates its download folder and missing parents. The control API also creates the enabled incomplete folder when it is missing.
- These automatic folders and folders created from the folder browser get mode `0775` and belong to the Transmission account.
- The folder browser refuses symbolic links, even ones that point inside `/data`.

:::tip
To keep downloads on more than one host folder, mount each one at its own path inside `/data`, such as `/data/movies`, instead of linking folders together.
:::

## Timezone

- `TZ` sets the container's time zone, and the default is `UTC`.
- It must name a zone installed in the image, such as `Europe/London`, using letters, digits, `.`, `_`, `+`, `-`, and `/`.
- An unknown zone stops startup with `config-init: TZ does not identify an installed timezone: <value>.`
