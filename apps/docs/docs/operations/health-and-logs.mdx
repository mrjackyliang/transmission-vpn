Use Docker health, the health routes, and the authenticated status route to tell whether the container is running and which connections can transfer.

## Docker health check

The image's <Terminology title="Docker's every-30-seconds check that the container is OK" to="/docs/reference/terminology#health-and-notifications">health check</Terminology> starts after 30 seconds, runs every 30 seconds, times out after 5 seconds, and marks the container unhealthy after 3 failed checks. It verifies that all five long-running s6 services are up, then sends `GET /api/v1/health/live` to port 22602 and requires a successful response.

```bash
docker compose ps
```

A container with no VPN connections can be healthy because liveness requires a working database and fail-closed runtime boundary, not an active tunnel. You can still open the web interface and create the first connection.

The control API, directory controller, Transmission runner, VPN controller, and web proxy are critical s6 services. An abnormal exit halts the container so Docker's restart policy can replace the complete appliance instead of leaving a partial service set running.

:::warning
A healthy container can have blocked VPN traffic. Docker health means the container can enforce its safety boundary and serve the control page.
:::

## Overall protection state

The authenticated `GET /api/v1/status` response includes `protectionState` and a count of protected and enabled connections:

| State            | Meaning                                                               |
|------------------|-----------------------------------------------------------------------|
| `protected`      | Every enabled connection is protected.                                |
| `partial`        | At least one enabled connection is protected and at least one is not. |
| `blocked`        | Connections exist, but none of the enabled connections is protected.  |
| `setup-required` | There is no usable default connection, or setup is incomplete.        |
| `error`          | The firewall state cannot be confirmed.                               |

The sidebar and VPN page use the same overall state. A partial state means protected connections can still transfer while another connection is blocked.

## Each connection and Transmission

The `connections` list in `GET /api/v1/status` reports each saved connection separately. It includes:

- Its name, default and enabled flags, and VPN state.
- Provider, tunnel, interface, endpoint, pool position, attempt, last error, and state time.
- WireGuard engine and last handshake when they apply.
- Its Transmission state, private bind address, RPC port, and peer port.

A Transmission state can be `starting`, `ready`, `exited`, or `missing`. The **VPN** page shows the connection state, and operations that need its daemon wait for `ready`.

## Health routes

Both health routes answer on port 22602 without a sign-in:

| Route                      | Response                                                                                                                                                                                                    |
|----------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `GET /api/v1/health/live`  | `200` with `{"status":"live"}` while the database answers and the startup and firewall files exist. It can stay live during setup, a partial state, or blocked reconnects.                                  |
| `GET /api/v1/health/ready` | `200` only when the default connection is protected and its Transmission is ready. Otherwise it returns `503` with `not-ready`, the overall `protectionState`, or `unavailable` when status cannot be read. |

```bash
curl --include http://<docker-host>:22602/api/v1/health/ready
```

Use <Terminology title="Is the default VPN protected and Transmission ready?" to="/docs/reference/terminology#health-and-notifications">readiness</Terminology> when a monitor should require the default connection to work. Use <Terminology title="Is the container alive, even if the VPN is down?" to="/docs/reference/terminology#health-and-notifications">liveness</Terminology> when it should require only a working container and safety boundary.

## Read logs

```bash
docker compose logs --follow app
```

Every app and startup script writes plain, single-line records in this shape; logs are never JSON:

```text
<ISO time> <LEVEL> <component>: <message>
```

Structured details follow the message as `name=value` fields on the same line. Embedded newlines are escaped, so each line records one fact.

| Look for                                                                                                               | Meaning                                                                                                                               |
|------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| `INFO config-init: Runtime identity 1000:1000 and app paths are ready.`                                                | Startup checks passed, here with example IDs.                                                                                         |
| `INFO firewall-init: Transmission egress is blocked through the legacy backend.`                                       | The firewall backstop is installed, here with the legacy backend.                                                                     |
| `INFO vpn-controller: VPN controller blocked all VPN egress at startup`                                                | Every protected source address is blocked before connections are restored.                                                            |
| `INFO firewall-protect: Transmission egress is restricted to <interface> from <address> with SNAT <provider-address>.` | One connection's private address is allowed through its tunnel and translated to its provider address.                                |
| `INFO firewall-block: Transmission egress through <interface> is blocked (<reason>).`                                  | One connection was blocked. The reason follows the line.                                                                              |
| `INFO vpn-controller: VPN state changed connectionId=<id>`                                                             | One connection changed state. The line also gives its slot, state, provider, tunnel, profile, attempt, and error.                     |
| `INFO transmission: Transmission daemon is ready connectionId=<id>`                                                    | One Transmission answered its first RPC check. The line also gives its private bind address.                                          |
| `ERROR transmission: Transmission daemon did not become ready` or `ERROR transmission: Transmission daemon exited`     | A connection's Transmission failed during startup or stopped. Use its `connectionId` with the status response.                        |
| `INFO control-api: moving Transmission torrent` and `INFO control-api: moved Transmission torrent`                     | A torrent move started and completed. The lines include source and target connection IDs; the completion line also includes warnings. |
| `WARN control-api: Transmission torrent move failed`                                                                   | A move failed. The source torrent is kept when the target add fails.                                                                  |
| `INFO web-proxy: web proxy listener opened`                                                                            | The web proxy is listening. Individual requests still wait when their login's connection is blocked.                                  |
| `INFO vpn-controller: openvpn` or `INFO vpn-controller: wireguard-go`                                                  | Tunnel process output, with credentials and keys replaced by `[redacted]`.                                                            |
| `INFO control-api: control API is ready`                                                                               | The web interface and API are listening.                                                                                              |
| `ERROR control-api: control API stopped error=<reason>`                                                                | The control plane stopped on an unrecoverable error.                                                                                  |

## Runtime status files

The container keeps current state under `/run/transmission-vpn/`:

| File                                      | Contents                                                                                             |
|-------------------------------------------|------------------------------------------------------------------------------------------------------|
| `config.ready`                            | Runtime identity and time zone after startup checks.                                                 |
| `firewall.backend`                        | `legacy` or `nft`.                                                                                   |
| `firewall.interfaces`                     | Protected tunnel, private address, and provider address entries.                                     |
| `firewall.ready`                          | Firewall state, backend, protected interfaces, and Transmission user ID.                             |
| `vpn.status.d/<connection-id>.json`       | One connection's VPN state, slot, tunnel, endpoint, DNS servers, attempt, and last error.            |
| `vpn.status`                              | A compatibility copy of the default connection's VPN status.                                         |
| `transmission-state/<connection-id>.json` | One Transmission's `starting`, `ready`, or `exited` state, RPC port, private address, and peer port. |
| `transmission-config/blocklists.json`     | Desired enabled state, HTTPS sources, update interval, and latest manual request.                    |
| `transmission-state/blocklists.json`      | Merger state, schedule, total ranges, per-source results, and retained-copy timestamps.              |
| `services/transmission.ready`             | The default Transmission identity, or the `no-connections` phase before a connection exists.         |
| `web-proxy-state/status.json`             | `off`, `listening`, `waiting-for-vpn`, or `error`.                                                   |

```bash
docker compose exec app ls /run/transmission-vpn/vpn.status.d
```

Runtime files are diagnostic details. Use the API status response for a stable combined view.
