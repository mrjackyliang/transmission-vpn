Run several VPN connections in one Docker container. Each connection has its own Transmission and lets that daemon's traffic out only through its verified OpenVPN or WireGuard tunnel.

## What Is Transmission VPN?

Transmission VPN is a Docker image that bundles Transmission 4.1, OpenVPN, <Terminology title="The VPN protocol that signs in with a key, not a password" to="/docs/reference/terminology#vpn-connections">WireGuard</Terminology>, and a web interface that manages them. A <Terminology title="When the VPN drops, traffic stops instead of leaking" to="/docs/reference/terminology#leak-protection">fail-closed</Terminology> firewall confines each Transmission to its own tunnel.

It replaces the <Terminology title="The old Synology script this Docker image replaces" to="/docs/reference/terminology#container-and-services">legacy project</Terminology>, a Synology script that bound Transmission to a VPN connection managed by the NAS.

## Why Use Transmission VPN?

1. Blocks each Transmission whenever its VPN connection isn't verified, so a dropped tunnel doesn't let that daemon connect from your own address.
2. Downloads the official server lists of PureVPN, Private Internet Access, IPVanish, NordVPN, Surfshark, IVPN, and Mullvad on request, so you can pick a server without hunting for profile files.
3. Accepts a <Terminology title="Your own .ovpn or .conf file for any VPN service" to="/docs/reference/terminology#custom-profiles">custom profile</Terminology> from another OpenVPN or WireGuard service, so a provider without a built-in list can still be used.
4. Runs several connections at once, each with its own Transmission, tunnel, peer port, and torrent list behind one interface.
5. Tries an ordered <Terminology title="Backup servers to try in order when one fails" to="/docs/reference/terminology#providers-and-endpoints">pool</Terminology> of up to 128 <Terminology title="One VPN server you can connect to" to="/docs/reference/terminology#providers-and-endpoints">endpoints</Terminology>, so one unreachable server doesn't stop a connection attempt.
6. Shows each connection and the combined <Terminology title="One word saying whether your traffic is safe right now" to="/docs/reference/terminology#leak-protection">protection state</Terminology>, so you can tell what can transfer without reading logs.
7. Gives every torrent a <Terminology title="Decides a torrent's folder and which VPN it uses" to="/docs/reference/terminology#torrent-profiles">profile</Terminology> that owns its download folder and VPN connection.
8. Lets other devices and containers select a VPN connection through an opt-in <Terminology title="Lets other devices browse through your VPN on port 22605" to="/docs/reference/terminology#remote-access">web proxy</Terminology>.

## What's Included

- **Transmission 4.1** — Built from the official source of the newest 4.1 release. Each VPN connection runs its own daemon, without Transmission's own web interface.
- **OpenVPN and WireGuard** — Each connection uses one of the two <Terminology title="OpenVPN or WireGuard; every endpoint in a pool shares one" to="/docs/reference/terminology#vpn-connections">tunnel types</Terminology>. The <Terminology title="Firewall rules that drop anything not going through a VPN" to="/docs/reference/terminology#leak-protection">firewall boundary</Terminology> keeps each daemon on its selected tunnel.
- **Eight provider options** — PureVPN, Private Internet Access, IPVanish, NordVPN, Surfshark, IVPN, and Mullvad, each with an official <Terminology title="The provider's server list you pick endpoints from" to="/docs/reference/terminology#providers-and-endpoints">catalog</Terminology>, plus Custom for your own `.ovpn` or `.conf` file.
- **Web interface** — Torrents, VPN, <Terminology title="A Transmission app on your phone or desktop" to="/docs/reference/terminology#remote-access">Remote apps</Terminology>, Settings, and Notifications pages, with **Sign-in and security** in the account menu. Each page has a bookmarkable [address](/docs/torrents/managing-torrents/#navigate-between-pages), and phones use **Torrents**, **VPN**, **Apps**, and **More** tabs.
- **Notifications** — Alerts sent to ntfy, Telegram, email, and eight other services when the VPN drops or comes back, a torrent finishes or fails, or sign-in is locked, as covered in [Notifications](/docs/alerts/notifications/).
- **Torrent profiles** — One unique folder and effective VPN connection per profile, plus label, paused, seeding, speed, priority, peer, and queue defaults. Named profiles add automatic matching, and the **Default profile** handles everything unmatched.
- **<Terminology title="A Transmission app on your phone or desktop" to="/docs/reference/terminology#remote-access">Remote app</Terminology> access** — An optional, password-protected <Terminology title="Makes all connections look like one Transmission to apps" to="/docs/reference/terminology#remote-access">compatible RPC</Terminology> route that combines every connection's torrents and gives each app its own login.
- **Web proxy** — Optional HTTP and SOCKS5 access for private-network clients, with a VPN connection selected for each login.
- **Private LAN access** — The web interface and compatible RPC route remain reachable from standard private IPv4 networks while each Transmission stays confined to its tunnel.
- **Health reporting** — A Docker <Terminology title="Docker's every-30-seconds check that the container is OK" to="/docs/reference/terminology#health-and-notifications">health check</Terminology> plus <Terminology title="Is the container alive, even if the VPN is down?" to="/docs/reference/terminology#health-and-notifications">liveness</Terminology> and <Terminology title="Is the default VPN protected and Transmission ready?" to="/docs/reference/terminology#health-and-notifications">readiness</Terminology> routes that need no sign-in.

## What It Doesn't Do

- It doesn't set up <Terminology title="Inbound ports for peers; this image never opens them" to="/docs/reference/terminology#vpn-connections">port forwarding</Terminology> through your VPN service or your router.
- It doesn't serve HTTPS, because the web interface uses plain HTTP on port 22602.
- It doesn't carry over the DSM VPN profile or Task Scheduler jobs of the <Terminology title="The old Synology script this Docker image replaces" to="/docs/reference/terminology#container-and-services">legacy project</Terminology>. The import wizard reads its Transmission 3 or 4 config and brings over supported settings, folders, and torrents.
