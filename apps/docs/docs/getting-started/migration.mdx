Move a Transmission 3 or 4 configuration and its existing downloads with the import wizard, then use the legacy-variable map when the old setup came from the <Terminology title="The old Synology script this Docker image replaces" to="/docs/reference/terminology#container-and-services">legacy script</Terminology>.

## What Changed

- The <Terminology title="The old Synology script this Docker image replaces" to="/docs/reference/terminology#container-and-services">legacy script</Terminology> ran on Synology DSM, connected a VPN profile defined in DSM, and changed the bind address of the Synology Transmission package.
- The Docker image runs its own Transmission, OpenVPN, and <Terminology title="The VPN protocol that signs in with a key, not a password" to="/docs/reference/terminology#vpn-connections">WireGuard</Terminology>, so it doesn't use DSM's VPN client or the Synology Transmission package.
- OpenVPN and WireGuard are the only supported protocols, so L2TP and PPTP connections can't move over.
- VPN connections still need to be set up in the web interface, while the import wizard can bring over supported Transmission settings, folders, and torrents.

The last release of the <Terminology title="The old Synology script this Docker image replaces" to="/docs/reference/terminology#container-and-services">legacy script</Terminology> is tagged [`v1.3.2`](https://github.com/mrjackyliang/transmission-vpn/tree/v1.3.2) in the GitHub repository.

## Legacy Variables

| Legacy variable                                         | In the Docker image                                                                                                                                                                                                                                                                                                              |
|---------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `VPN_CONFID`, `VPN_CONFNAME`, `VPN_PROTO`, `VPN_UINAME` | Not used. Choose a provider or upload a <Terminology title="Your own .ovpn or .conf file for any VPN service" to="/docs/reference/terminology#custom-profiles">custom profile</Terminology> on the **VPN** page instead.                                                                                                         |
| `VPN_TYPE`, `VPN_INTERFACE`                             | Not used. Each connection's slot sets its interface, `tun<slot>` for OpenVPN or `wg<slot>` for WireGuard.                                                                                                                                                                                                                        |
| `VPN_RETRY`, `VPN_INTERVAL`                             | Not used. After the tunnel drops, reconnects continue without a limit, with a <Terminology title="How long to wait between reconnect rounds" to="/docs/reference/terminology#providers-and-endpoints">retry interval</Terminology> of 10 seconds.                                                                                |
| `PORT_FWD`                                              | No equivalent. The old check only tested whether a port was open, and the image doesn't set up <Terminology title="Inbound ports for peers; this image never opens them" to="/docs/reference/terminology#vpn-connections">port forwarding</Terminology>.                                                                         |
| `IP_CHECK`                                              | No equivalent. Fixed <Terminology title="Proof the tunnel works before any torrent can use it" to="/docs/reference/terminology#leak-protection">tunnel verification</Terminology> checks run on every connect.                                                                                                                   |
| `TRANS_USER`, `TRANS_GROUP`                             | <Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PUID`</Terminology> and <Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PGID`</Terminology>, which set the account that runs Transmission. |
| `TRANS_VAR`                                             | Not used. Each connection's Transmission settings live under `/config/transmission/<connection-id>` and are rebuilt at every start.                                                                                                                                                                                              |

## Move from Another Transmission

Mount the old Transmission config folder read-only at `/import`, and mount its download folders under `/data` so the wizard can map them without copying the data:

```yaml title="compose.override.yml"
services:
  app:
    volumes:
      - /path/to/old/config:/import:ro
      - /path/to/downloads:/data/downloads
```

1. Stop the old Transmission so its `settings.json`, `torrents`, and `resume` files stay consistent while they are read.
2. Set <Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PUID`</Terminology> and <Terminology title="Which user owns your downloads on the host" to="/docs/reference/terminology#storage-and-keys">`PGID`</Terminology> to an account that can write to the mounted download folders, using IDs from 1 to 60000.
3. Add and test a default VPN connection, as covered in [Connect to a VPN](/docs/vpn/connecting/).
4. Open **Settings**, find **Backup**, select **Import…**, and choose **Another Transmission**.
5. Use `/import` as the **Config folder**, map every old folder to its location under `/data`, and review the generated profiles and supported settings.
6. Select **Import** in **Review**. Every torrent is added paused. One whose data is found is re-checked and returned to its saved paused or running state; one whose data is not found stays paused as **Data missing**.

The old default download folder becomes the <Terminology title="Where torrents go when no named profile matches" to="/docs/reference/terminology#torrent-profiles">Default profile</Terminology>'s folder. Other download folders and any included empty sibling folders become named <Terminology title="Decides a torrent's folder and which VPN it uses" to="/docs/reference/terminology#torrent-profiles">profiles</Terminology>, and the old incomplete folder carries over separately.

[Export and Import](/docs/configuration/export-and-import/#import-from-another-transmission) covers every wizard step, the supported settings, and the **Not brought over** list.

## What the Legacy Script Doesn't Carry Over

- **DSM VPN profiles** — Upload the `.ovpn` file as a <Terminology title="Your own .ovpn or .conf file for any VPN service" to="/docs/reference/terminology#custom-profiles">custom profile</Terminology> or pick a built-in provider.
- **Task Scheduler jobs** — Jobs that ran the script's `start`, `stop`, or `repair` commands aren't needed, because <Terminology title="Starts the firewall first and keeps every service running" to="/docs/reference/terminology#container-and-services">s6-overlay</Terminology> supervises the services inside the container.
