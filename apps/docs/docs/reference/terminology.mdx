## Container and Services

| Term                     | Also known as                  | Definition                                                                                                                                                                                                                                                                                                                                                                                         |
|--------------------------|--------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **legacy project**       | legacy script, Synology script | The original Transmission VPN shell script for Synology NAS, released as versions 1.0.0 through 1.3.2, which bound the Synology Transmission package to a VPN connection managed by DSM. The import wizard can read its Transmission 3 or 4 config, but its DSM VPN profile and Task Scheduler jobs don't carry over.                                                                              |
| **control plane**        | `control-api`                  | The unprivileged service that serves the web interface, the API, and live updates on port 22602, serves the optional compatible RPC route on port 9091, and sends notifications. It runs as `PUID:PGID` and stays reachable while the VPN is down.                                                                                                                                                 |
| **control port**         | `22602/tcp`                    | Port 22602, which carries the web interface and the API over plain HTTP. The container always listens on it, and a different host port is set by changing the host side of the port mapping, such as `8080:22602`.                                                                                                                                                                                 |
| **RPC port**             | `9091/tcp`                     | Port 9091, Transmission's usual port, which carries only the optional `/transmission/rpc` route over plain HTTP. The container always listens on it, and a different host port is set by changing the host side of the port mapping, such as `8091:9091`.                                                                                                                                          |
| **VPN controller**       | `vpn-controller`               | The privileged service that starts and stops OpenVPN and WireGuard tunnels, verifies them, works through their endpoint pools, and switches per-connection firewall rules. The control plane reaches it over a local socket limited to status, connect, restore, disconnect, and set-default, plus a second socket that opens connections outside the VPN for provider catalogs and notifications. |
| **directory controller** | `directory-controller`         | A small service that runs as `PUID:PGID` and lists, creates, or deletes one empty folder under `/data` for the folder browser. It never deletes recursively, shows only real folders, and refuses symbolic links.                                                                                                                                                                                  |
| **s6-overlay**           | process supervisor             | The process supervisor that runs as the container's first process. It starts the firewall before the VPN controller and Transmission runner, restarts services that exit, and removes the firewall rules only after the protected services stop.                                                                                                                                                   |
| **TUN device**           | `/dev/net/tun`                 | The kernel device that OpenVPN and userspace WireGuard use to create tunnel interfaces. The container stops at startup when it is missing.                                                                                                                                                                                                                                                         |
| **NET_ADMIN**            | —                              | The Docker capability that lets the container manage its firewall rules and tunnel interfaces, without privileged mode. Without it, firewall setup fails and the container stops.                                                                                                                                                                                                                  |

## Storage and Keys

| Term                  | Also known as                      | Definition                                                                                                                                                                                                                                                                                                                                                                             |
|-----------------------|------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **PUID and PGID**     | —                                  | The user and group IDs that run every unprivileged app service and own app state and downloads, `1000` by default. They must be integers from 1 to 60000.                                                                                                                                                                                                                              |
| **data mount**        | `/data`                            | The `/data` folder, which holds every profile folder and the incomplete folder. Torrent data can't be stored in `/data` itself.                                                                                                                                                                                                                                                        |
| **incomplete folder** | `transmission.incompleteDirectory` | The folder that holds unfinished data when **Use incomplete folder** (`transmission.incompleteDirectoryEnabled`) is on, until Transmission moves it to the torrent's profile folder. It stays reserved even while the setting is off.                                                                                                                                                  |
| **config volume**     | `/config`                          | The `/config` folder, which holds the database, the installation key, Transmission's configuration folder, and the optional managed configuration file. It is recommended to back up the whole folder together.                                                                                                                                                                        |
| **installation key**  | `installation.key`                 | The key at `/config/keys/installation.key`, stored as 64 lowercase hexadecimal characters plus a newline in a mode `0600` file inside a mode `0700` folder. It encrypts the authenticator app's secret, VPN profile contents and credentials, and notification secret fields. A start without it makes a new key and removes those secrets; a key from another database stops startup. |

## Accounts and Backups

| Term                  | Also known as                         | Definition                                                                                                                                                                                                                                                                |
|-----------------------|---------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **claim code**        | One-time code, `setupCode`            | The one-time code, printed in the container logs as `setupCode`, that creates the administrator account on a new installation. It looks like `XXXXX-XXXXX-XXXXX`, expires after 30 minutes, and is replaced each time the container starts unclaimed.                     |
| **claim secret file** | `/run/secrets/transmission-vpn-claim` | A file you mount at `/run/secrets/transmission-vpn-claim` to use your own claim secret instead of a generated code. It must hold 12 to 256 characters and works for 24 hours after the container starts.                                                                  |
| **Confirm it's you**  | —                                     | The fresh account check before an export or import, using the password and current authenticator code when enabled, or a passkey. It issues a five-minute grant that works once, only for that operation and browser session.                                             |
| **export file**       | —                                     | A portable JSON backup of the sections selected under **Settings** > **Backup** > **Export…**. It moves supported configuration to another installation without the source installation key, contains selected secrets in plain text, and never contains downloaded data. |

## VPN Connections

| Term                    | Also known as  | Definition                                                                                                                                                                                                                                                                                        |
|-------------------------|----------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **VPN connection**      | connection     | One saved VPN setup with its own slot, tunnel, peer port, private address, and Transmission. Its torrents send traffic only through that connection's tunnel.                                                                                                                                     |
| **default connection**  | —              | The VPN connection used when nothing selects another one: new Default-profile adds, unresolved remote-app pattern ties, and web proxy logins set to **Default**. It also carries DNS for every Transmission.                                                                                      |
| **tunnel**              | tunnel type    | The VPN protocol a connection uses, OpenVPN on `tun<slot>` or WireGuard on `wg<slot>`, so each connection has its own interface. Every endpoint in a pool uses the same tunnel, and a provider that offers both shows a **Tunnel** switch on the **VPN** page.                                    |
| **WireGuard**           | —              | A VPN protocol that signs in with a key pair instead of a username and password. The container runs it with the host's WireGuard kernel module when the host has one, and with userspace WireGuard otherwise.                                                                                     |
| **userspace WireGuard** | `wireguard-go` | WireGuard run by `wireguard-go`, a program in the image, when the host's kernel has no WireGuard module. It needs no extra container settings but is slower on low-end NAS processors, and **Tunnel** reads **WireGuard (userspace)** while it's in use.                                          |
| **private key**         | —              | The secret half of your WireGuard key pair, 44 characters of base64 that end in `=`, taken from a custom WireGuard file or the provider's **Sign-in** fields. It's encrypted with the installation key and never written to logs, though a freshly confirmed export can include it in plain text. |
| **tunnel address**      | —              | The IPv4 address, such as `10.68.12.34/32`, that a WireGuard provider assigned to your key. Mullvad and IVPN ask for it, Surfshark uses `10.14.0.2/16` when it's left empty, and NordVPN always uses `10.5.0.2/32`.                                                                               |
| **handshake**           | Last handshake | The key exchange a WireGuard tunnel repeats with its server about every two minutes, which shows the server still answers. A new connection waits up to 30 seconds for the first one, and a handshake older than 3 minutes means the server is gone.                                              |
| **port forwarding**     | forwarded port | Opening an inbound port so peers can connect to Transmission. No provider adapter requests a forwarded port, and Transmission's router port mapping (UPnP and NAT-PMP) is turned off.                                                                                                             |

## Leak Protection

| Term                    | Also known as | Definition                                                                                                                                                                                                                                                                                                                                                                     |
|-------------------------|---------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **fail-closed**         | —             | Preventing traffic from leaving through a non-VPN route. Transmission and web proxy traffic is blocked before a tunnel starts, during reconnects, after a disconnect, and during shutdown, and only the VPN controller can open a connection outside the VPN.                                                                                                                  |
| **leak**                | —             | Traffic that leaves outside the VPN tunnel and exposes your real address, such as a DNS lookup or a connection made during a reconnect.                                                                                                                                                                                                                                        |
| **firewall boundary**   | —             | The iptables rules that drop every new connection the container opens outside a VPN tunnel, except loopback traffic other than DNS, replies, IPv6 neighbor discovery, and packets the VPN controller marks. They don't match which account sends a packet, so they work on kernels without the owner match, such as Synology's, and they cover IPv6 when the container has it. |
| **firewall backend**    | —             | The iptables variant the container uses, `legacy` or `nft`, chosen at startup with legacy tried first. The container stops when neither works.                                                                                                                                                                                                                                 |
| **tunnel verification** | —             | The checks a connection must pass before Transmission or the web proxy may use its tunnel: its slot interface exists, its private address routes through it, DNS succeeds through the protected route, and an outside TCP connection succeeds. They run on every connect and reconnect, and for WireGuard only after the first handshake.                                      |
| **protection state**    | —             | The combined safety state for enabled connections: `protected` when all are protected, `partial` when some are, `blocked` when none are, `setup-required` before a usable default exists, or `error` when firewall state can't be confirmed.                                                                                                                                   |
| **protected DNS**       | —             | The resolver setup used by every Transmission: DNS leaves through the default connection's private address and tunnel, using its provider or custom servers. Lookups stop while the default connection is down.                                                                                                                                                                |

## Providers and Endpoints

| Term                              | Also known as        | Definition                                                                                                                                                                                                                                                    |
|-----------------------------------|----------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **provider adapter**              | adapter              | The built-in integration for one VPN service, which supplies its tunnels, catalog sources, credential fields, and capabilities. Adapters provide data only, so they can't run code or change the firewall.                                                    |
| **endpoint**                      | server               | One VPN server you can connect to, stored as a validated OpenVPN profile or WireGuard configuration. Each has a name, a location when one is known, a server address and port, and for OpenVPN a protocol (UDP or TCP).                                       |
| **endpoint catalog**              | catalog              | A provider's official list of endpoints for one tunnel, downloaded when you select **Refresh list**. Every entry must pass validation before the new list replaces the old one, and WireGuard lists hold no keys.                                             |
| **endpoint pool**                 | Fallback order, pool | The ordered list of up to 128 endpoints from one provider and one tunnel, shown as **Fallback order** on the **VPN** page. The first endpoint is primary, and failures never remove an endpoint from it.                                                      |
| **endpoint strategy**             | strategy             | The rule for choosing the next endpoint after the tunnel drops. **Sticky** retries the current endpoint first, **Ordered** moves to the next one, and **Randomized** shuffles the pool on each cycle.                                                         |
| **retry interval**                | —                    | The wait between reconnect cycles after the tunnel drops, from 3 to 600 seconds with a default of 10. Retries continue until an endpoint passes verification.                                                                                                 |
| **last-known-good configuration** | —                    | The most recent configuration for one VPN connection that passed **Test and connect**, saved with its credentials encrypted. That connection restores it at startup and after a failed test, unless **Disconnect and block** turned automatic reconnects off. |

## Custom Profiles

| Term                      | Also known as              | Definition                                                                                                                                                                                                                                                                                                                                                                                   |
|---------------------------|----------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **custom profile**        | `.ovpn` file, `.conf` file | Your own OpenVPN `.ovpn` file or WireGuard `.conf` file, uploaded on the **VPN** page when **Provider** is Custom. Each OpenVPN `remote` line becomes an endpoint in file order with its certificates and keys inline, while a WireGuard file supplies one endpoint and its own private key.                                                                                                 |
| **profile normalization** | —                          | The rewrite every OpenVPN profile and WireGuard file goes through before it's saved, keeping only allowed settings and rejecting scripts, commands, plugins, proxies, route overrides, and file references. OpenVPN profiles get full-tunnel routing on their slot interface, and WireGuard files get `AllowedIPs = 0.0.0.0/0` and `PersistentKeepalive = 25` and lose their IPv6 addresses. |
| **trust anchor**          | —                          | The part of an OpenVPN profile that proves the server's identity: an inline `<ca>`, `<tls-auth>`, or `<tls-crypt>` block, or a `peer-fingerprint` line. A profile without one is rejected, while a WireGuard file relies on its peer's `PublicKey` instead.                                                                                                                                  |
| **inline block**          | —                          | Certificate or key text pasted into the profile between tags such as `<ca>` and `</ca>`. Lines that point to separate files, such as `ca ca.crt`, are rejected.                                                                                                                                                                                                                              |

## Torrent Profiles

| Term                | Also known as   | Definition                                                                                                                                                                                                                                                                                                 |
|---------------------|-----------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **profile**         | torrent profile | The download folder, effective VPN connection, labels, and paused, seeding, speed, priority, peer, and queue defaults assigned to a torrent. A profile owns one unique folder, and changing a torrent's profile moves its files and transfers it to another Transmission when the VPN connection differs.  |
| **Default profile** | Default role    | The profile listed first and used when no named profile matches, with the same editable fields as a named profile but no name patterns. Its folder is the `transmission.downloadDirectory` setting, its read-only VPN connection follows the default connection, and it can't be deleted.                  |
| **Needs a profile** | —               | The state of a paused remote-app add whose name matched several profiles after its folder and labels chose none. It waits in the Default profile's folder and connection until **Choose a profile** moves it, applies that profile's labels and limits, and starts it unless **Start paused** is selected. |
| **label**           | tag             | A free-form tag attached to a torrent; profile labels supply the starting list, but labels change without changing the torrent's profile, folder, or VPN connection. A label is saved the first time it's used, and renaming or deleting it updates every torrent that uses it.                            |

## Remote Access

| Term               | Also known as                  | Definition                                                                                                                                                                                                                                                                                                                           |
|--------------------|--------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **web proxy**      | `web-proxy`                    | The opt-in HTTP and SOCKS5 service on port 22605 that lets private-network devices and containers use a VPN connection. Each login selects a connection or follows the default, and its DNS and destination traffic use that tunnel.                                                                                                 |
| **remote app**     | Transmission client            | A third-party Transmission client that controls the container through compatible RPC. It connects to `/transmission/rpc` on port 9091 with its own RPC login.                                                                                                                                                                        |
| **compatible RPC** | RPC proxy, `/transmission/rpc` | The opt-in `/transmission/rpc` route on port 9091 that lets remote apps use Transmission's RPC protocol. It shows all connections as one Transmission, checks each request's RPC login, and routes supported methods to the right native daemon.                                                                                     |
| **native RPC**     | —                              | One Transmission daemon's RPC listener, reachable only on container loopback and never published. Slot 0 starts at `127.0.0.1:9092`, and later slots use the following ports.                                                                                                                                                        |
| **RPC login**      | —                              | The username and generated password one remote app uses for compatible RPC. The password is shown once and stored as a digest, and the login can be regenerated or deleted without affecting other apps.                                                                                                                             |
| **API token**      | bearer token                   | A scoped credential for automating the API, sent as a bearer token that starts with `tvpn_`, with a name, scopes such as `torrents:read` or `vpn:write`, and an optional expiry. Creating, editing, or revoking one needs a signed-in browser session, and tokens can't manage notifications or download a torrent's finished files. |

## Settings and Managed Configuration

| Term                      | Also known as        | Definition                                                                                                                                                                                                                                                                             |
|---------------------------|----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **setting source**        | —                    | Where a setting's current value comes from, reported by the settings API as `default`, `user`, `managed-seed`, or `managed-lock`. In Settings, a `managed-lock` row shows **Locked**.                                                                                                  |
| **apply impact**          | —                    | How a saved setting reaches the running container, reported as `live` or `transmission-restart`. A setting that needs a restart shows **Transmission restart required** and keeps the saved value until you confirm the restart.                                                       |
| **revision**              | —                    | A counter that goes up with every saved settings change. A save based on an older revision is refused, so a change made in another browser is never overwritten silently.                                                                                                              |
| **controlled restart**    | Restart Transmission | The `POST /api/v1/transmission/restart` request with `{"confirm": true}`, which applies saved settings and restarts every connection's Transmission without restarting the container. The Settings page shows a **Restart Transmission** button for it after a saved setting needs it. |
| **managed configuration** | `managed.json`       | The optional `/config/managed.json` file that seeds or locks settings. It's validated with the same rules as the web interface and read at every start, and an invalid file stops the container.                                                                                       |
| **managed seed**          | seed                 | A managed configuration value that fills a setting only when nothing is saved for it yet. Later changes in the web interface take precedence.                                                                                                                                          |
| **managed lock**          | lock, Locked         | A managed configuration value that overrides a setting while the file contains it, shown as **Locked** and not editable. The saved value returns when the lock is removed and the container restarts.                                                                                  |

## Health and Notifications

| Term                         | Also known as          | Definition                                                                                                                                                                                                                                                                                                               |
|------------------------------|------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **health check**             | Docker health check    | The image's Docker health check, which runs every 30 seconds, confirms that every long-running s6 service is up, and requires a successful `GET /api/v1/health/live` on port 22602. With no connections, the setup-ready container can still be healthy.                                                                 |
| **liveness**                 | `/api/v1/health/live`  | The `GET /api/v1/health/live` route, which returns `200` while the database answers and the startup and firewall state files exist, even when the VPN is down. It needs no sign-in.                                                                                                                                      |
| **readiness**                | `/api/v1/health/ready` | The `GET /api/v1/health/ready` route, which returns `200` only when the default connection is protected and its Transmission is ready, and `503` otherwise. It needs no sign-in.                                                                                                                                         |
| **notification destination** | destination            | One place alerts go, such as an ntfy topic, a Telegram chat, an email address, or a webhook, set up on the **Notifications** page. Each has a name, a service, the events it hears about, and the service's fields.                                                                                                      |
| **notification event**       | event                  | Something the container can send an alert about: **Saved secrets were removed**, **Sign-in locked**, **VPN dropped**, **VPN back up**, **Torrent finished**, **Torrent error**, or **Profile choice needed**. Each destination chooses its own, and all seven are checked when you add one.                              |
| **secret field**             | —                      | A destination field, such as a token, password, or webhook URL, that's encrypted with the installation key and kept out of ordinary pages and read routes. Leaving it blank on edit keeps the saved value, a freshly confirmed export can include it in plain text, and a start without the installation key removes it. |
| **notification payload**     | webhook payload        | The JSON body that webhook and Reverse Proxy for ntfy destinations receive, with `version`, `app`, `event`, `title`, `message`, `priority`, `tags`, `occurredAt`, and `details`. Its `app` is always `transmission-vpn`.                                                                                                 |
